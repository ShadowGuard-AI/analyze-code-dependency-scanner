analyze-code-dependency-scanner

Lists the dependencies a repository declares and checks them against a small built in example table only.

Open the repo Usage

The whole table

The built in example table holds exactly two entries:

requests2.28.0
django3.2.0

Every declared dependency is checked against those two entries, and nothing wider.

The limits, stated exactly

This scanner does not query public vulnerability databases and does not check whether packages are outdated. A result with no flags only means no declared package matched requests at 2.28.0 or django at 3.2.0.

Install and usage

cd analyze-code-dependency-scanner
pip install -r requirements.txt

./analyze-code-dependency-scanner [params]

Parameters

-hshow help message and exit
-ono description provided in the source; printed that way rather than given a guessed job
-foutput format: csv or json. Defaults to csv
-pno description provided in the source; printed that way rather than given a guessed job
--ignore-vulnerabilitiespath to a JSON file containing a list of vulnerabilities to ignore

The files

main.py, the scanner itself, holding the two entry table. requirements.txt, its dependency (pandas). LICENSE, the MIT License. Full notes are in the repo README.

A short list, checked bottle by bottle, and nothing claimed beyond it.
