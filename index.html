analyze-code-dependency-scanner

Lists the dependencies a repository declares and checks them against a small built in example table only. That table, held in main.py, has exactly two entries, requests at 2.28.0 and django at 3.2.0.

Surface float: what this tool is and what it is not

This tool does not query public vulnerability databases and does not check whether packages are outdated, so a run with no flags means only that no declared package matched those two entries.

Tag: Focused on Data analysis and reporting.

git clone https://github.com/ShadowGuard-AI/analyze-code-dependency-scanner

Second depth band: the dive itself

./analyze-code-dependency-scanner [params]

That line is the whole of the documented running instructions. The README gives no worked example, no sample repository, and no sample output, and this band says so rather than inventing a demonstration catch.

The bed: the parameters, shell by shell

-h shows the help message and exits.

-f sets the output format, csv or json, and defaults to csv.

--ignore-vulnerabilities takes the path to a JSON file containing a list of vulnerabilities to ignore.

-o: No description provided. -p: No description provided. Both are printed exactly that way, as named but undocumented.

Read the source on GitHub

What no flags means

No flags means no match against requests 2.28.0 and django 3.2.0, nothing wider. Anyone who needs current vulnerability data will need a different tool alongside this one.
